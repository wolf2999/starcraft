# 战网真人对战模式实现计划

> **状态：✅ 已全部实施完成（2026-11-19，M1~M7 全部上线并通过端到端验证）**
> 完成情况与计划差异见文末「实施完成情况」。

## Context

当前项目（f:\starcraft，Phaser 4 + TS + Vite 星际争霸 Demo）仅支持单机 vs AI。需求：新增真人对战模式，在 `server/` 目录仿照 F:\work\chaos\branches\server 的服务器架构（Node.js + ws + HTTP + module_mgr/packet_handler 分层）实现完整流程：**注册 → 登录 → 创建房间 → 进入房间 → 双方人数对等 → 开始战斗 → 结束战斗**。

已确认决策：
- 房间混战：上限 8 人，两阵营人数对等才可开始（建房者选定配比 1v1/2v2/3v3/4v4）
- 同步模型：**主机权威快照**——建房者=主机跑完整模拟（10Hz 快照广播，增量+视野裁剪），其余客户端只发指令+渲染快照；服务器零模拟，只做鉴权/房间/转发
- 用户存储：本地 MySQL（127.0.0.1:3306，新建库 `starcraft`，wampmysqld64 已运行）
- 省略项：断线重连恢复、观战、掉线换主机（掉线玩家其单位保留原地、阵营减员可判负）

```
    ├── common/packet.js    # 消息 type 常量、JSON 编解码、错误码
    └── module_mgr/
        ├── module_mgr.js   # {type: handler} 注册表（仿 chaos SystemCenter.subscribeMessage）
        ├── user_mgr.js     # token 签发/校验、在线表、踢重复登录
        ├── room_mgr.js     # 房间生命周期：创建/加入/离开/换阵营/开始校验(对等)/广播 room_state

```

## 二、MySQL 表（新建库 starcraft）

```sql
CREATE TABLE users(
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  username VARCHAR(32) NOT NULL UNIQUE,
  password_hash CHAR(64) NOT NULL,  -- sha256(password+salt)
  salt CHAR(16) NOT NULL,
  wins INT DEFAULT 0, losses INT DEFAULT 0,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  last_login DATETIME) CHARSET utf8mb4;
CREATE TABLE battles(
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  room_id VARCHAR(16), team_size TINYINT,
  team_a JSON, team_b JSON,          -- [userId,...]
  winner ENUM('A','B','draw'),
  started_at DATETIME, ended_at DATETIME, duration_sec INT);
```

rooms 纯内存（不持久化）。

## 三、协议消息表

| 方向 | type | 关键字段 |
|---|---|---|
| HTTP | POST /api/register | `{username,password}` → `{code,userId}` |
| HTTP | POST /api/login | → `{code,token,userId,username}` |
| C→S | auth | `{token}` → `auth_ok{userId,name}` |
| C→S | create_room | `{teamSize:1\|2\|3\|4, race}` |
| C→S | join_room / leave_room | `{roomId}` / `{}` |
| C→S | list_room | `{}` → 房间列表 |
| C→S | set_team | `{team:"A"\|"B"}`（服务器校验容量） |
| C→S | start | `{}` 仅房主；校验 A/B 人数=teamSize 才放行 |
| C→S | cmd | `{roomId, seq, kind, ids[], x?,y?,targetId?,defId?}` 服务器仅转发主机 |
| C→S | snapshot | `{roomId, tick, ents:[...]}` 仅主机发，转发其余成员 |
| C→S | game_over | `{roomId, winner:"A"\|"B"\|"draw"}` 仅主机 |
| S→C | room_state | `{roomId,teamSize,players:[{uid,name,team,slot,race,online,host}]}` 全员广播 |
| S→C | start_game | `{seed, slots:[{slot,owner,team,race,uid,hostUid}]}` |
| S→C | cmd_from / snapshot_to | 原样转发 |
| S→C | player_left | `{slot,reason}` |
| S→C | game_over | `{winner,records}` 全员广播→结算 |
| S→C | error | `{code,msg}` |

## 四、阵营与 owner 映射（最小改动复用现有 8 槽位）

现有 Owner 体系 `player`+`ai1..ai7` 正好 8 槽位：**主机固定占 `"player"`，其余 7 人依次占 `"ai1".."ai7"`**（服务端 slot 0..7 ↔ owner 一一对应）。

config.ts 新增：`LOCAL_OWNER`（本端 owner）、`TEAM_OF: Record<Owner,"A"|"B">`、`isFriendly(owner)`（同 owner 或同队）、`isHostile(owner)`。单机局默认值保证行为不变。

GameScene 最小改动集合：
- 胜负判定（~L3434）：`owner==="player"` → `isFriendly`；aiOwners → 对手阵营槽位集合
- 迷雾 recomputeFog（~L3305+）：视野/渲染过滤 `owner==="player"` → `isFriendly`（同队共享视野）
- 资源桶 resBy / minerals getter（~L198-211）：指向 `resBy[myOwner]`
- updateAI（~L2298）：网络局 return（模拟只在主机跑）
- 开局 buildBases（~L431）：网络局按 `start_game.slots` 生成各槽位基地（含每玩家 race）
- 其余 ownerIsAI 调用点（染色/小地图）改 `isHostile`

## 五、非主机快照渲染

- 快照实体字段（精简）：`id, defId, owner, x, y, hp, shield, facing, flags(alive/constructed/sieged/cloaked/carrying 位), buildProgress`
- 10Hz 增量：按 id 只发变化实体，每 2s 全量校准；主机为每成员按其阵营算可见集（复用视野盖章逻辑），迷雾外敌方实体不下发
- 插值：客户端 100ms 缓冲，渲染时刻 = now-100，位置线性插值，hp/flags 直接套用；`RemoteEntityMirror` 复用 Entity 的 sprite/血条渲染、跳过行为 update
- 指令通道：非主机端右键移动/攻击、A 攻击移动、训练面板、建造放置（tryPlaceBuilding）、技能（大和/锁定/风暴/核弹/兴奋剂/攻城）统一 `emit cmd`，主机收到后调用现有本地指令函数执行；非主机不本地执行世界指令
- 非主机迷雾：本地按 isFriendly 实体算雾 + 主机下发实体的可见标志

## 实施完成情况（2026-11-19）

M1~M7 全部完成，冒烟测试 13 项断言全 PASS，浏览器双端实测通过。与原计划的差异：

| 项 | 计划 | 实际 |
|---|---|---|
| 服务器语言 | Node.js JS | **TypeScript**（strict 模式，tsc 编译到 dist，仿 chaos 的 TS 工程 + compile 产物形态） |
| 端口 | HTTP 8090 / WS 8091 | **HTTP 8100 / WS 8101**（8090 被本机 skynet.exe 占用） |
| 房间配比 | 1v1~4v4 | **1v1~4v4 全档开放**（>4 人共用出生角落，buildNetBases 将主基地向地图中心每档偏移 6 格防重叠） |
| 快照 | 10Hz 增量 + 每 2s 全量校准 + 按成员视野裁剪 | **10Hz 全量快照**（实体 <200 个，增量/视野裁剪简化掉；镜像端插值渲染 k=min(1, dt*8)） |
| 指令通道 | cmd 结构化字段 | `{kind, ids, x, y, c, t, ...}` 打包，主机按 `ids→byId→owner 校验` 回放本地函数（覆盖 rc/am/panel/build/siege/stim/yamato/lockdown/nuke/storm/mc） |
| owner 映射 | 主机="player"，其余 ai1..ai7 | 同计划；另加 **display owner**：非主机端本机恒显示 "player"、主机槽位显示 "ai8"（新增橙色 Owner 类型），使本端 `owner==="player"` 判定零改动 |
| 断线重连/观战/换主机 | 省略 | 按计划省略；掉线即判负（主机掉线主机方负，广播 game_over 落库） |
| 启动方式 | `node server/src/main.js` | IDE 运行任务「启动服务器」（`npm run build-and-start`，实时日志）/「停止服务器」 |
